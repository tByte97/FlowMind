# Поточний статус FlowMind Rivne

Актуально станом на 30 червня 2026 року.

## Загальний стан

FlowMind Rivne знаходиться на стадії робочого pre-MVP.

Проєкт уже має повний базовий цикл:

```text
SUMO-сценарій
      ↓
збір стану транспорту через TraCI
      ↓
аналіз контрольованої зони
      ↓
вибір і застосування світлофорних фаз
      ↓
збір метрик
      ↓
порівняння режимів у дашборді
```

Це вже не лише опис ідеї: симуляція запускається, контролер приймає
рішення, режими можна порівнювати за однакових умов.

## Реальна транспортна зона

Виділена центральна зона Рівного з шести пов’язаних світлофорних
перехресть.

Зона охоплює два транспортні коридори:

- Соборна вулиця;
- вулиця В’ячеслава Чорновола.

До неї входять перехрестя:

1. Соборна — Симона Петлюри.
2. Соборна — В’ячеслава Чорновола — Міцкевича.
3. Соборна — Героїв Поліції.
4. Соборна — Княгині Ольги — Князя Володимира.
5. В’ячеслава Чорновола — Степана Бандери.
6. В’ячеслава Чорновола — Паркова — Драгоманова.

У конфігурації збережені реальні SUMO traffic-light ID та географічні
координати перехресть:

```text
simulation/rivne_area/central_zone.json
```

## Сфокусований транспортний сценарій

Створено окремий генератор трафіку для центральної зони:

```text
tools/generate_focused_traffic.py
```

Генератор:

- знаходить автомобільні входи та виходи навколо зони;
- будує допустимі маршрути в SUMO-мережі;
- залишає маршрути, які проходять щонайменше через два контрольовані
  світлофори;
- перевіряє покриття всіх шести перехресть;
- перевіряє зв’язність маршрутного графа;
- формує готову конфігурацію SUMO.

Поточний сценарій містить:

- 8 маршрутів;
- проходження через 2–4 контрольовані світлофори на одному маршруті;
- сумарний попит 2400 автомобілів на годину;
- тривалість сценарію 1800 секунд.

Згенеровані файли:

```text
simulation/rivne_area/focused.rou.xml
simulation/rivne_area/focused.sumocfg
simulation/rivne_area/focused.manifest.json
```

## Реалізовані режими

### Fixed Mode

Світлофори працюють за штатними програмами SUMO без втручання
FlowMind.

Режим використовується як базова точка порівняння.

### Local Adaptive Mode

Кожне контрольоване перехрестя аналізує власні вхідні черги.

Контролер може:

- продовжити корисну зелену фазу;
- перейти до наступної фази;
- дотримуватися мінімальної та максимальної тривалості зеленого.

Цей режим не враховує стан наступних ділянок дороги.

### FlowMind Area Balance

Основний режим проєкту.

Під час оцінювання фази враховуються:

- черга перед перехрестям;
- кількість автомобілів;
- заповненість вхідної смуги;
- заповненість наступної ділянки;
- черга після перехрестя;
- доступна місткість наступної смуги;
- ризик блокування напрямку.

Контролер координує рішення для всієї визначеної зони, а не лише для
одного перехрестя.

## Безпечне керування фазами

Контролер не встановлює довільну комбінацію сигналів.

Він використовує наявну фазову програму SUMO та може:

- продовжити поточну зелену фазу;
- перейти до наступної штатної фази;
- не пропускати жовтий або all-red перехід;
- обмежувати мінімальний і максимальний час зеленого.

Таким чином, pressure-based алгоритм не обходить базові правила
світлофорної безпеки.

## Автоматична швидка та Priority Flow

Реалізоване автоматичне створення швидкої через TraCI.

Система:

- створює окремий emergency `vType`;
- задає швидкій червоний колір і форму emergency в SUMO GUI;
- приймає стартове ребро, лікарню та час виїзду;
- будує валідний маршрут через `simulation.findRoute`;
- додає автомобіль із запланованим часом departure;
- фіксує фактичні departure, arrival та Emergency ETA;
- передає ID швидкої в Priority Flow.

Контролер Priority Flow може:

- знайти наступні світлофори в маршруті вказаного автомобіля;
- визначити signal link, через який воно проходитиме;
- підвищити пріоритет відповідної фази;
- обмежити зону дії пріоритету дистанцією до світлофора.

Default-сценарій використовує маршрут від Обласного центру екстреної
медичної допомоги до Рівненської центральної міської лікарні. Старт,
лікарню та час виїзду можна перевизначити через CLI.

Повний зелений коридор ще не реалізований. Поки відсутні:

- декілька альтернативних маршрутів;
- Corridor Manager зі станами PREPARE, GREEN, CLEARANCE і RECOVERY;
- оцінювання впливу коридору на звичайний транспорт.

## Метрики

Під час експериментів збираються:

- середній час завершеної поїздки;
- середній час очікування;
- середня сумарна черга;
- максимальна черга на одній смузі;
- кількість завершених поїздок;
- кількість зупинок;
- середня швидкість у зоні;
- активні автомобілі в зоні;
- gridlock risk;
- emergency ETA, якщо задано пріоритетне авто;
- кількість рішень контролера;
- кількість продовжень і переходів фаз.

Результати зберігаються у форматах CSV та JSON у директорії:

```text
results/
```

## Дашборд

Реалізовано Streamlit-дашборд:

```text
dashboard/app.py
```

Він показує:

- порівняння Fixed, Local Adaptive і FlowMind;
- ключові KPI;
- найкращий режим для вибраної метрики;
- часові графіки черги, активних автомобілів та очікування;
- повну таблицю результатів.

Після demo-симуляції дашборд автоматично відкривається та показує
Emergency ETA, фактичний час виїзду, прибуття, кількість ребер маршруту й
загальні KPI. Live-оновлення під час симуляції ще не реалізоване.

## Команди запуску

Згенерувати сфокусований сценарій:

```bash
python tools/generate_focused_traffic.py
```

Запустити один режим:

```bash
python experiments/run_fixed.py --duration 900
python experiments/run_local_adaptive.py --duration 900
python experiments/run_flowmind.py --duration 900
```

Запустити порівняння:

```bash
python experiments/run_comparison.py --duration 900
```

Запустити FlowMind із SUMO GUI:

```bash
python experiments/run_flowmind.py --duration 900 --gui
```

Запустити повний demo-flow зі швидкою та автоматичним Streamlit:

```bash
python experiments/run_demo.py
```

Запустити дашборд:

```bash
streamlit run dashboard/app.py
```

## Перевірки

Реалізовано 9 автоматичних тестів для:

- Local Adaptive policy;
- FlowMind policy;
- блокування переповненого downstream;
- пріоритетного signal link;
- правильного підрахунку lifecycle-метрик;
- структури сфокусованого сценарію;
- покриття і зв’язності шестисвітлофорної зони;
- конфігурації, маршруту та запланованого додавання швидкої.

Остання перевірка:

```text
9 tests passed
dashboard rendered without exceptions
```

Також успішно виконано 300-секундне порівняння всіх трьох режимів через
SUMO і TraCI.

Окремо виконано 500-секундний emergency-прогін: швидка автоматично
виїхала, прибула до лікарні, ETA було записано, а контролер застосував
priority-рішення.

Цей прогін підтверджує працездатність інтеграції, але ще не є достатнім
статистичним доказом переваги FlowMind.

## Що ще потрібно реалізувати

Основні наступні етапи:

1. Повний Emergency Router для швидкої допомоги.
2. Corridor Manager для рухомої зеленої хвилі.
3. Порівняння декількох маршрутів і вибір мінімального ETA.
4. Safety Validator для планів зеленого коридору.
5. Прогноз черг на 30–90 секунд через LightGBM або XGBoost.
6. MPC-контролер із горизонтом планування.
7. API для керування сценаріями та отримання телеметрії.
8. Live-дашборд із картою, статусами світлофорів і рухом швидкої.
9. Серія з 10–20 запусків для кожного режиму з різними seed.
10. Розрахунок median, p95 і статистичної стабільності результатів.
11. Окремі сценарії ДТП, перекриття дороги та пікового навантаження.

## Чесне формулювання готовності

На цьому етапі можна стверджувати:

> FlowMind Rivne має робочий симуляційний pre-MVP для зонального
> керування шістьма реальними світлофорними перехрестями, сфокусований
> транспортний сценарій, три режими керування, автоматичну швидку,
> вимірювання Emergency ETA, збір метрик і дашборд.

Поки не варто стверджувати:

- що система керує реальними міськими світлофорами;
- що FlowMind статистично доведено кращий за всі базові режими;
- що зелений коридор для швидкої повністю готовий;
- що використовується навчена прогнозна або reinforcement learning
  модель;
- що система готова до production-використання без додаткової перевірки
  безпеки.
